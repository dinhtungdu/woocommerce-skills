# WooCommerce verified compatibility facts

Load only when the changed surface intersects a listed fact.

- At PR #67696 implementation head `9390f4c438`, WordPress 7.1 active-theme `settings.viewport.mobile` and `settings.viewport.tablet` values drive Product Filters Mobile and Tablet boundaries; evidence proved custom 600px/900px and default 480px/782px fallbacks. Evidence: prepare-pr-52 preflight.
- Supported viewport settings are sanitized upstream: WordPress 7.1 and Gutenberg 23.6+ accept non-negative numeric `px`/`em`/`rem`, reject malformed values, and discard `tablet <= mobile`; WordPress 7.0 without that Gutenberg capability falls back to `782px`. Do not duplicate upstream validation in Product Filters. Evidence: WOOAIRR-148 investigation.
- WordPress preserves arrays supplied for registered query vars. Woo comma-list parsers must reject non-strings before `trim()`/`explode()` and treat unsupported arrays as absent, not flatten them; for taxonomy `pa_color`, the canonical attribute query var is `filter_color`. Evidence: WOOAIRR-147 investigation and accepted follow-up review.
- Treat values crossing WordPress hook and filter boundaries as extension-controlled even when documentation declares a type. Before typed calls or returns, preserve valid values and validate, normalize, or reject invalid ones; do not blindly cast arrays or objects, and add malformed-value regression coverage when introducing strict types. `manage_{taxonomy}_custom_column` demonstrated the risk: an extension-supplied `null` became fatal after WooCommerce added a `string` return type. Evidence: investigation and verified fix.
- Product Collection pagination delegates to WordPress Interactivity Router. Router can disable unmanaged runtime `<link>`/`<style>` nodes absent from fetched HTML; WooCommerce should not generically re-enable document stylesheets. Gutenberg #76031 owns fix; `forcePageReload` is bounded temporary mitigation.
- Single Product must seed native WordPress context at the selected-product boundary. Core Title/Excerpt compatibility temporarily substitutes the resolved product post and restores the exact enclosing post; Product Template must consume that context so Product Collection location filters retain their source product. Evidence: #45374 verified focused tests.
- Product Collection daily random SQL seeds created only during PHP query construction can split cached pagination across site-local midnight. A URL token can pin a journey only when the page cache varies on or bypasses it; caches that ignore it remain unsolved. Evidence: #67611 investigation.
- PR #68116 corrected Woo-generated classic archive pagination so page-one links are canonical. Its public `woocommerce_pagination_args` `base`/`format` pair changed; two observed noncore modifiers replace the pair and remain compatible, so practical installed-consumer breakage is unconfirmed. Preserve paired base/format semantics in future changes; do not treat a theoretical format-empty case as regression evidence. Evidence: #67953 accepted PR description and #68116 compatibility review.
- WordPress 6.8.2–7.1 attachment generation writes fresh metadata with empty `sizes` before generating subsizes. Destructive Woo lazy regeneration remains when a Woo size is removed after `init`, metadata lacks it, and non-square featured image forces regeneration: Core cannot generate unregistered requested size, then Woo skips restoration because returned metadata lacks it. Preserve latest unfiltered foreign metadata; define nested precedence; avoid stale whole-record recovery writes. Evidence: #60577 investigation, #67458 review, #66271 review.
- Skipping rating lookup jobs while reviews are disabled can leave `average_rating` and `rating_count` stale after re-enable; settings toggle triggers no regeneration. Accepted existing behavior: catch-up is manual or separate scope. Evidence: #66524.
- Customer email-verification prompt treats missing **Confirm email address** setting as enabled and disabled setting as false default, then applies `woocommerce_customer_email_verification_should_show_prompt` last so extensions can override either state. Evidence: #67994.
- Single Product password and Product Add-Ons legacy-form redirects preserve exact non-empty raw query strings—including `search=?` and lone `0`—and rewrite root across root, subdirectory, multisite, and `index.php` permalinks. Evidence: #67402.
- At PR #67579 head `a04d648`, `@woocommerce/components` depends on `window.wcSettings`: `PhoneNumberInput` reads country data at module evaluation; `Search` reads variation settings at call time. Namespace/SSR, malformed, delayed localization remain unsafe. Explicit empty variation separator must not be replaced via `||`. Evidence: #67579.
- `woocommerce_ajax_variation_threshold` is max child count preloaded inline; above uses `wc-ajax=get_variation`; `0`/`false` forces AJAX for any variable product with children. Default shipped 20 in 2.4.0, rose to 30 in 2.4.7; no primary source documents empirical calibration. Evidence: history.
- Product Add-Ons 8.3.0 adds `cart_item_data['addons'] = []` for ordinary classic adds, and core cart-ID generation includes that key. Do not infer non-canonicality from cart metadata or reconstruct a cart ID from partial item data. Evidence: cart design review.
- Variation sale-price persistence clears a sale value greater than or equal to regular price. Bulk-adjustment UI must accept explicit `0`/`0%` and let persistence clear it, but reject empty or malformed input before normalization so it cannot clear an existing sale. Evidence: WOOAIRR-282 accepted fix.
- `wc_get_text_attributes()` returns unvalidated strings (including `"0"`), not term IDs. Taxonomy metadata readers must retain `absint`, zero filtering, and assigned-term intersection before `WC_Product_Attribute::get_terms()`, which treats strings as names. Evidence: PR #65604 review.
- Virtual settings translated only by `woocommerce_admin_settings_sanitize_option_*` are bypassed by V4 General Settings direct `update_option` writes. Support that route separately and cover it with a V4 PUT regression test. Evidence: PR #68710 review.
- With attribute lookup enabled, `FilterData` collection counts use variation-level lookup eligibility while Store API `/wc/store/v1/products` and Product Collection `QueryBuilder` still use parent `tax_query` filtering. Count/result divergence is an accepted temporary limitation; collection-data coverage must assert published terms count and disabled-only terms are omitted, without locking current Store API behavior. Evidence: PR #68482 review.
